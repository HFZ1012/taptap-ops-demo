# 玩家信号 · 产品运营工作台

面向 TapTap 产品运营岗位的独立交互作品，非官方产品。原生 HTML/CSS/JavaScript，无需安装依赖。

## 运行

在此目录运行 `npm start`，浏览器打开 http://127.0.0.1:4177 。也可直接双击 `dist/index.html` 体验大部分功能；本地服务器方式更适合保存状态与复制文本。

运行 `npm test` 检查核心业务规则。

## 岗位职责映射

| 岗位任务 | Demo 实现 |
| --- | --- |
| 客服系统日常运营、上升事件 | 工单建单、分派、状态流转、回复草稿、处理轨迹、样例 SLA |
| 客服外包管理 | 按团队汇总待处理/已解决工单，人工四项质检、培训备注，修改回复后作废旧评分 |
| AI 客服能力优化 | 可启停知识条目、规则匹配回复、知识引用、转人工分流、四个回归场景 |
| 内外网情报建设 | 四渠道虚构样例、粘贴导入、精确文本去重、关键词分类、原文证据、优先级排序、简报导出 |
| 体验改善闭环 | 从反馈聚类建立需求、分配负责人、方案跟进、填写验证记录、同步看板 |

## 3 分钟演示路线

1. 运营总览发现登录异常，进入情报中心核对原文与来源。
2. 选择一条登录反馈转工单，生成回复建议，指派升级专席，保存处理说明。
3. 将登录问题聚类生成产品需求，查看验证目标和证据，推进到方案设计。
4. 在 AI 客服实验室关闭登录知识条目，观察相同问题转人工；打开后重新运行测试。
5. 在团队质检中评价回复，回到总览观察统计变化，导出情报简报。

## 数据与 AI 边界

- 所有初始玩家、团队、工单、趋势、业务数据均为虚构。历史趋势是独立的示例序列，不是当前 24 条明细的历史统计。
- 分类和回复为确定性关键词 + 知识模板模拟，不调用大模型。匹配分是启发值，不是模型置信度；负面表达和多意图可能误分类。
- 多渠道仅演示来源标记与导入，未接入 TapTap、社群、竞品接口、抓取、定时监测或消息发送。
- 状态保存在当前浏览器 localStorage，没有服务器数据库或多用户协作。页面显示的 SLA 时点固定为 2026-09-14 12:00。
- 未提供生产客服能力，保存回复不会发送消息，标记已验证不会部署任何产品改动。目标值和演示验证结果不能作为真实业务收益。
- 导出 Markdown 包含当前导入的原文，展示前应自行检查内容。关于面板提供重置按钮；重置会清除该浏览器中的演示修改。

## 结构

- `dist/index.html`：页面壳与导航。
- `dist/styles.css`：桌面/移动端样式。
- `dist/model.js`：样例数据、分类、评分、业务动作和简报。
- `dist/app.js`：六个模块、对话框和本地状态。
- `server.cjs`：本地静态服务器。
- `tests/model.test.cjs`：核心业务规则测试。

## 后续真实接入的边界

在获得数据源授权与服务端环境后，可接入工单/反馈 API、定时采集及去重、带引用的模型结构化输出、人工审批与审计、真实 SLA 告警和上线前后指标对比。生产系统应由服务端保护模型凭证并实现鉴权，不能把密钥写入前端。
